# Nifty Quant Screener

The Nifty Quant Screener is an automated, end-to-end quantitative market scanner and portfolio health analyzer for the Nifty 500 universe. It evaluates daily OHLCV data against a strict six-point technical criteria (utilizing moving averages, RSI, MACD, and volume spikes) to identify high-probability breakout and momentum setups. It also features a Streamlit dashboard for visualizing daily opportunities and analyzing the technical health of a user's uploaded portfolio.

## Prerequisites

* **Python 3.12+**
* Git

## Local Setup Instructions

A new developer can get the pipeline running locally in just a few minutes.

**1. Clone the repository**

```bash
git clone https://github.com/yahsaka/nifty-quant-screener.git
cd nifty-quant-screener

```

**2. Create and activate a virtual environment (Recommended)**

```bash
# Windows
python -m venv venv
.\venv\Scripts\activate

# macOS / Linux
python3 -m venv venv
source venv/bin/activate

```

**3. Install dependencies**

```bash
pip install -r requirements.txt

```

**4. Configure Environment Variables**
The project relies on a `.env` file for customizable thresholds, backtest parameters, and directory paths.

```bash
cp .env.example .env

```

*You can run the project using the default values in `.env.example`, or tweak them (like altering the `BACKTEST_HOLD_DAYS` or `SCREENER_TRADE_READY_MIN_SCORE`) to observe different behaviors.*

## Running the Pipeline

The system is broken down into modular scripts. To populate the dashboard with today's data, you must run the data fetcher and screener before launching the app.

### Step 1: Fetch Market Data

```bash
python src/data_fetcher.py

```

* **What it does:** Downloads the latest Nifty 500 list from the NSE (with fallbacks if the NSE API drops). It then updates the local Parquet-based OHLCV cache (`data/ohlcv_cache/`) using `yfinance`.

### Step 2: Run the Screener

```bash
python src/screener.py

```

* **What it does:** Evaluates the broader market regime (Nifty 50 vs. 200 EMA) and processes all cached stocks against the technical rules engine. It outputs the qualifying setups to `data/latest_screener_results.json`.

### Step 3: Run the Dashboard

```bash
streamlit run app.py

```

* **What it does:** Launches the interactive web UI where you can view today's setups, inspect interactive Plotly charts, and upload a broker holding CSV to check your portfolio's 200-day EMA health.

### Step 4: Run the Backtest (Optional)

```bash
python src/backtest.py

```

* **What it does:** Runs historical simulations on the cached OHLCV data using the same technical rules applied in `screener.py`. It outputs a summary table of Win Rates, Avg Returns, and Profit Factors directly to the terminal.

## Automation via GitHub Actions

This project is designed to run completely hands-off via GitHub Actions.

A scheduled cron job (configured in `.github/workflows/`) automatically executes `data_fetcher.py` and `screener.py` daily after the Indian market closes. The workflow commits the newly generated `latest_screener_results.json` directly back to the `main` branch.

Because Streamlit Cloud is linked to the `main` branch, it automatically detects the updated JSON file and refreshes the live dashboard without requiring manual redeployment.

## ⚠️ Disclaimers and Limitations

**Not Financial Advice:** This repository and the accompanying dashboard are for educational and research purposes only. The outputs generated by this tool do not constitute investment advice, financial guidance, or a recommendation to buy or sell any security.

**Known Backtest Limitations:**
The historical modeling in `backtest.py` relies on a strict, mechanical execution system that has deliberate constraints:

1. **No Discretionary Exits:** The backtest assumes a rigid time-based exit (e.g., at the close of the 20th session) or a strict ATR-based stop-loss. It does *not* model partial profit-taking (e.g., selling 50% at +10%) or moving stops to breakeven, which a human trader might realistically do.
2. **Gap Execution:** If the market opens below the calculated stop-loss price, the backtest exits at the *weaker opening price* to accurately penalize gap-downs, but true live market liquidity during severe gap-downs may result in worse fills.
3. **Slippage & Costs:** While the backtest variables (`ENTRY_SLIPPAGE_BPS`, `ROUND_TRIP_COST_BPS`) inject conservative friction into the results, they are static constants. Real-world slippage on illiquid Nifty 500 micro-caps will vary wildly.
